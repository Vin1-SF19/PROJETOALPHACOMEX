# Echo — APIs CheckList prontas para Nova

Código somente nos dois worktrees da story. Nenhum banco, env/config real, push ou deploy. `Result<T>` está em `lib/checklist/types.ts` (Painel sob src); testar `result.ok`, usar `result.data` apenas no sucesso e `result.error.message/code` no erro. Não usar o shape legado `{data?,error?:string}`. Actions exigem guards persistidas; capabilities são apresentação, não autoridade. Datas são Date em Server Actions; eventos recovery usam ISO.

## Painel

Imports de `@/actions/checklist`:

- `listarAnalistasChecklist()` → Result de array `{id,nome,imagemUrl,ativo,legado,totalEmpresas}`. Contagens independentes da página. Sidebar começa Todos; null está em Todos. Não tem pseudoanalista Sem Pasta.
- `listarEmpresasChecklist({analistaId?,semAnalista?,busca?,tipo?,status?,page?,pageSize?})` → Result `{items,totalCount,page,pageSize}`. Default25/max100; resetar página quando filtro mudar. Item: `{id,clienteId,razaoSocial,cnpj,nomeFantasia,status,embasamento,mesProtocolo,linkGrupo,analista,tipoAtivo,checklistAtivoId,resumo,revision,capabilities}`. `id` é atendimento String, `clienteId` é master Int.
- `obterEmpresaChecklist(empresaId,{checklistId?})` → detalhe `{id,clienteId,cliente:{id,razaoSocial,nomeFantasia,cnpj,regimeTributario},contaPortal?,analista,tipoAtivo,status,embasamento,mesProtocolo,linkGrupo,revision,checklistAtivoId,checklist,checklists,historical,resumo,capabilities}`. `checklists` lista cabeçalhos/IDs/tipos. `checklist` selecionado é null ou cabeçalho + `itens`; item contém id/codigo/secao/descricao/complemento/status/observacao/obrigatorio/ordem/atualizadoEm/_count.documentos, SEM array documental. Buscar documentos paginados separadamente. Histórico não ativa tipo; `historical` true implica canEdit false.
- `criarAtendimentoChecklist({mutationId,clienteId,clienteOperacionalId? OU novaConta:{nome,email},analistaId?,tipo?})` → `{atendimento:detalhe,credencialInicial?:string,replayed}`. A senha inicial criptográfica aparece somente na primeira resposta; não há action separada para criar conta órfã. Analista comum dono forçado para si; líder escolhe elegível. Conta existente para não líder exige controle exclusivo comprovado dos atendimentos dela.
- `selecionarTipoChecklist({empresaId,tipo,expectedRevision,mutationId})` → detalhe completo confirmado. Criar/trocar são o mesmo núcleo; não chamar com dois parâmetros legados. MODEL_EMPTY impede instância vazia. `criarChecklist` e `trocarEmbasamentoChecklist` aliases recebem ESTE objeto.
- `atualizarEmpresaChecklist({empresaId,patch:{status?,embasamento?,mesProtocolo?:string|null,linkGrupo?:httpsURL|null},expectedRevision,mutationId})` → detalhe. Tipo, dono, conta e master não são campos desse patch.
- `atualizarItemChecklist({itemId,patch:{status?,observacao?:string|null},expectedRevision,mutationId})` → detalhe. Omitir preserva, null limpa. Salvar observação só ao mudar, aguardar confirmação, usar revisão retornada. Nenhum status legado novo.
- `atribuirAnalistaChecklist({empresaId,analistaId,expectedRevision,mutationId})` → detalhe; somente líder.
- `listarDocumentosChecklist({empresaId,itemId?,checklistId?,excluidos?,page?,pageSize?})` → Page documento DTO. Default50/máx100. Documento `{id,nome,url,uploadedByCliente,observacao,criadoEm,deletadoEm,deletadoPorCliente,uploadedByUsuarioId,uploadedByContaId,deletadoPorUsuarioId,deletadoPorContaId}`. `url` é handler autenticado, nunca URL privada/storage key. `_count.documentos` do item é total, inclusive removidos; usar listagem/totalCount correto para badge ativos/removidos.
- `registrarDocumentoChecklist({itemId,recibo,expectedRevision,mutationId})` → DocumentoDTO. Depois recarregar detalhe para revisão do agregado; não inventar incremento no cliente em replay/no-op.
- `excluirDocumentoChecklist({documentoId,expectedRevision,mutationId})`, `restaurarDocumentoChecklist(mesmoObjeto)` e `atualizarObservacaoDocumento({...mesmoObjeto,observacao:string|null})` → DocumentoDTO. Só ocultar após confirmação e recarregar revisão. Histórico não permite escrita; restauração interna requer objeto disponível.
- `obterHistoricoChecklist({empresaId,page?,pageSize?})` → Page eventos com id/tipo/revision/atorTipo/atorUsuarioId/atorContaId/dados/createdAt.
- `listarHistoricoDocumentosChecklist({empresaId?,page?,pageSize?})` → Page DocumentoDTO + itemId/itemCodigo/itemDescricao/checklistId/tipo/empresaId/razaoSocial/cnpj/analista. Global autorizado com paginação; usar ator de remoção real.

## Upload privado, download e ZIP — ambos aplicativos

Usar o fluxo direto para suportar até8MiB na Vercel (request de função limita4.5MB):
1. POST `/api/checklist/upload/iniciar`, JSON `{itemId,nome,mime,tamanhoBytes}` → Result `{recibo,pathname,clientToken,access:'private',expiresAt}`. São credenciais transitórias de upload, nunca armazenar em store/log/histórico.
2. `put(pathname,file,{access:'private',token:clientToken,contentType:mime,addRandomSuffix:false})` importado de `@vercel/blob/client`; só arquivo privado no caminho autorizado, sem overwrite. Não usar SDK servidor no navegador.
3. POST `/api/checklist/upload/finalizar`, JSON `{itemId,recibo}` → Result `{recibo,nome,tamanhoBytes,mimeType,verificado:true}`. Servidor lê o objeto privado limitado8MiB, verifica tamanho/MIME/magic bytes/hash. Sem isso o recibo não registra documento.
4. Action registrarDocumento/adicionarDocumento com recibo+CAS+mutationId. Retry mantém recibo/intenção; não aceitar URL/nome/autoria no comando. Reconsultar revisão do detalhe após confirmação.

Upload bruto pequeno também existe: Painel POST `/api/checklist/upload?itemId=...&filename=...`, Portal POST `/api/upload?itemId=...&filename=...`, body bytes + Content-Type; retorna recibo já verificado. Interface final deve preferir direto para todos os tamanhos. Uploadthing antigo do Portal foi fechado para impedir caminho público alternativo.

Download URL do DTO é `/api/checklist/documentos/:id/download`, nos dois apps, com ACL/no-store/stream limitado. Painel ZIP `/api/checklist/:empresaId/documentos/zip?escopo=ATIVO` default; `escopo=TODOS` explícito ou `checklistId=id` para instância histórica. Máx100docs/25MiB cada/100MiB total, deadline45s, fetch10s, concorrência3. Spool limitado em tmp e ZIP output streaming; nomes únicos e manifesto.json mesmo parcial. Não afirmar completo se manifesto aponta falhas.

## Eventos e central Painel

`@/actions/checklist/eventos`: `listarEventosChecklist({cursor?:{createdAt:ISO,id},limit?:1..100,somenteNaoLidos?:boolean})` → `{items:[{eventId,revision,tipo,empresaId,createdAt,lidoEm,dados}],nextCursor}`; cursor descendente estável. `marcarEventoChecklistLido(eventId)` → recibo durável. HTTP GET `/api/checklist/eventos?cursor=JSON&limit=50&naoLidos=true`; POST JSON `{eventId}` marca lido. `/api/notificacoes` agrega fonte `checklist:{items,nextCursor}` no envelope já existente. Sem segundo poller widget/shell; recovery usa paginação além dos50, dedup eventId e readstate.

Pusher canal `private-checklist-docs`, evento **`checklist-evento`**, payload `{eventId,revision,empresaId}`. Não usa mais payload/ID inventado de novo-documento-cliente. Um subscriber no shell, consumidores apenas store, unbind só callback. Claim/retry worker POST `/api/checklist/jobs/eventos`, Authorization Bearer segredo específico. O Portal grava journal transacional no banco compartilhado e não publica seu evento antigo diretamente; worker Painel publica depois do commit. Nenhuma fila/automação/tarefa BPM utilizada.
